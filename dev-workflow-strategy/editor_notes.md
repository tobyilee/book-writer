## 2. 구조·표기 결정

- **헤딩 수준:** 장 `#`, 절 `##`로 통일했다 (네 묶음이 모두 이렇게 썼고, 원고 골격의 앞부속 `##`과도 맞는다). 계획의 "소절 `###`"은 장 제목을 `###`로 쓴 계획 문서 안에서의 상대 표기로 봤다. "이 장의 핵심" 박스는 절과 같은 층위라서 `## 이 장의 핵심`으로 올렸다 (마지막 절 아래에 들어가 있던 문제 해소). EPUB 목차(toc-depth 2)에 해당 6장에서 한 줄씩 보인다.
- **"이 장의 핵심" 배치:** 4·8·9·10·11·13장 — 계획과 일치. 추가·삭제 없음.
- **부(部) 표시:** 1장 본문이 "1부와 2부", "1부부터 5부까지"를 언급하므로 목차를 부별로 묶고 서문에 부 구성을 적었다. 본문에 부 표지(`#`) 헤딩은 넣지 않았다 — `--split-level=1` 빌드에서 빈 장 파일이 생기기 때문.
- **용어 통일 (계획 "용어 표기" 기준):**
  - 12~14장의 맨 `main` 표기 60여 곳을 코드 표기 `` `main` ``로 (영문 인용문·mermaid 라벨·장 제목 제외).
  - 12~14장 "auto-merge" → "자동 머지" (6장이 소유 장이고 "자동 머지(auto-merge)"로 첫 등장).
  - 14장 "cherry-pick" → "체리픽" (2·3장 표기. 영문 인용문 안은 유지).
  - "GitHub은" → "GitHub는" (5·12장; 나머지 장 표기에 맞춤).
  - 12장 "풀 리퀘스트(PR)" 재풀이 삭제 (첫 등장은 1장).
  - 13장 YAML의 `actions/checkout@<full-commit-sha> # v{N}` → `# v7` (11장과 같은 확인값. factcheck_log 08장 확인값 checkout v7).
  - 14장 절 제목 "재고, 하나씩 바꾸기" → "먼저 재고, 하나씩 바꾸기" (3장의 "재고(inventory)"와 헷갈림 방지).
- **액션 버전:** 8~11·13장 전부 checkout v7 / setup-node v7 / cache v6 / upload-artifact v7 / download-artifact v8로 일치 확인. 값은 바꾸지 않았다.

- **4→5장:** 5장 둘째 문단 뒤에 연결 문단 추가 — 4장에서 세운 문의 규칙과, 그 문을 두드리는 PR로 넘어감.

- **콜백 정정:**
  - 7장 "12장과 13장에서 이 구성(two-step CI)을 자세히 본다" → 원리 12장 / 구성 13장으로 나눔 (12장은 two-step CI를 다루지 않음).
