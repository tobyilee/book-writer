## 계수 방법

`book-editing` 스킬의 규정대로 **코드 블록(``` 로 둘러싸인 영역, mermaid 포함)만 제외**하고 공백을 뺀 문자 수를 셌다. 표·불릿·인용은 본문으로 계수한다 — 이 책은 표가 산문을 대신해 논지를 나르는 자리가 많아(1장 버전 축 표, 6장 스타터 매트릭스, 8장 타임아웃 노브 표) 표를 빼면 실제 독서 부담이 과소평가된다.

> 참고: 표까지 제외하고 세면 중앙값이 4,378자로 내려가고 1·2·6·8장이 상대적으로 낮아진다. 아래 판정은 **표 포함 기준**이다.

## 3장 예외 인정 사유

3장(TypeScript 정본 워크스루)은 계획 5,500자 대비 −25.3%다. 확장 요청 대신 **예외로 기록한다.**

1. **코드가 곧 내용인 장이다.** 코드 포함 전체 문자 수는 6,117자로 12장 중 3위이고, 코드 블록 비중이 가장 높다(산문 4,108 / 전체 6,117 = 코드가 33%). 계획의 5,500자는 이 비중을 반영하지 않은 산문 기준 배정이었다.
2. **중앙값 기준으로는 정상 범위다**(87.3%, 밴드 하한 70% 위).
3. **분량을 늘리면 경계를 침범한다.** 3장이 더 쓸 수 있는 주제 — 오류 처리 심화, `bin`/배포, 도구 개수 논증, 디버깅 — 는 계획의 「챕터 간 경계」 표가 각각 5·9·7·8장 소관으로 못 박아둔 것들이다. 여기서 늘리면 중복 방지 규율이 깨진다.
4. 스타일 라운드 2에서 3장은 재작성을 거쳐 클로징이 적용 과제로 복원됐고(`wiki_list_spaces` 추가 과제), 그 과제가 분량 대신 독자의 손을 움직이는 자리를 맡는다.

**조치: 확장 요청 없음.** `editor_notes.md`에 기록해 Phase 4.5(`manuscript-reviewer`)가 뒤집을 수 있게 남긴다.
