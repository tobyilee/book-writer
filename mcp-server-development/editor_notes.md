## A. 편집자가 실제로 수정한 것 (전건 목록)

### A-1. 용어 통일 (챕터 파일에 반영)

`04_manuscript.md`가 아니라 **`chapters/{NN}_final.md`에 반영**했다. 재통합 시에도 살아남게 하기 위해서다.

| 수정 | 전 → 후 | 대상 | 근거 |
|---|---|---|---|
| 외래어 표기 | `디렉토리` → `디렉터리` ×2 | 1장 | 나머지 4개 장(2·4·11·12)이 전부 `디렉터리`. 표준 표기 |
| 오기 | `밀리스톤` → `마일스톤` ×1 | 6장 | milestone의 오기 |
| 저장소 지칭 통일 | `리포지토리`/`리포` → `저장소` ×10 | 6·9·11장 | 1·3·4·12장이 `저장소`를 쓰는데 9·11장만 `리포지토리`였다. 문맥 손상 없이 전건 치환 가능 |

치환 순서 주의(재실행 시): `리포지토리`를 먼저 바꾸고 그다음 단독 `리포`. 반대로 하면 `저장소지토리`가 된다.

**통일하지 않은 것** — 검사했고 정상 판정: 트랜스포트(11회, 대체 표기 없음) · 프리미티브 · 리비전(45회) · 핸드셰이크 · 커맨드(`명령어` 0회로 이미 일관) · 애너테이션(`어노테이션` 0회) · 컨텍스트(`콘텍스트` 0회) · 클로드(제품명 Claude Code/Desktop과 구분되어 일관).

### A-2. 10장 체크리스트 ↔ 부록 중복 조정 (`chapters/10_final.md`)

계획이 예고한 조정이다. 10장 말미의 4항목 체크리스트를 **삭제하지 않고** 그 뒤에 부록 포인터 한 줄을 넣었다.

> 넷은 이 장에서 다룬 것만 추린 출발점이다. 7장의 설계 단계 항목까지 합친 전체 목록은 책 뒤의 부록 「MCP 서버 보안 체크리스트」에 모아두었다.

**삽입 위치를 불릿 뒤 · 마지막 한 줄 앞으로 잡은 이유:** 10장의 클로징은 계획이 배정한 「한 문장 여운」이고 style-guardian 라운드 2가 12/12 배정 준수를 확인했다. 포인터를 맨 끝에 붙이면 그 여운("stdio를 벗어나는 순간…")이 무너진다.

7장은 이미 본문에 "책 뒤의 보안 체크리스트를 펴자"가 있어 **양쪽 포인터가 같은 부록 제목으로 해소된다.**

### A-3. 전환부 — 수정 없음 (점검 결과)

11개 인접 쌍을 전부 대조했고 **손댈 곳을 찾지 못했다.** 기록으로 남긴다.

| 경계 | 판정 |
|---|---|
| 1→2 | 문제 없음. 다만 1장의 "만들어봐야 안다"가 곧장 프로토콜 해부로 이어져 미세한 낙차가 있다 → **머리말의 빠른 경로 안내(3장→4장→1장)로 해소했다.** 본문은 손대지 않았다 |
| 2→3 | "무엇을 할 수 있지?" → 상황 가정. 매끄럽다 |

| 4→5 | 계획이 유일하게 허용한 다음 장 예고 구간. 의도대로 |
| 5→6 | "JVM에서 만들면 어떨까?" → Java SDK 릴리스 노트 인용. 매끄럽다 |
| 6→7 | "무엇을 만들 것인가" → 19% 수치. 이 책에서 가장 강한 전환 |
| 7→8 | 7장이 "그 이유는 8장에서" 복선을 두 번 심었고 8장이 받는다 |
| 8→9 | 적용 과제 → 상황 가정 |
| 9→10 | 9장이 세 질문(세션·판별·공격면)을 던지고 10장 첫 절이 그대로 받는다 |
| 10→11 | 한 문장 여운 → 인용. 11장이 10장 툴체인 논지를 명시 회수 |
| 11→12 | "얼마나 갈까?" → 1장 콜백. 계획의 매듭 구조 그대로 |

**콜백도 추가하지 않았다.** 장 간 상호 참조가 이미 촘촘하다(3↔5↔6 오류 케이스 3중 회수, 3→9 `bin` 키 회수, 7→8 설명 절단, 8→11 무신호 실패, 1→12 네 축 증명). 편집자가 더 심으면 과잉이다.

## B. 수정하지 않고 넘기는 것

### B-1. 3장 분량 (계획 대비 −25.3%)

`length_report.md`의 「3장 예외 인정 사유」 참조. 코드 비중이 가장 높은 정본 워크스루이고, 중앙값 기준으로는 정상 범위(87.3%)이며, 늘릴 만한 주제가 전부 계획의 챕터 경계 표에서 다른 장 소관으로 못 박혀 있다.

**Phase 4.5가 이 판단을 뒤집을 수 있다.** 뒤집는다면 3장 확장이 아니라 계획의 분량 배정을 실측에 맞춰 조정하는 쪽을 권한다 — 12장 전부가 계획을 밑도는 것은 3장만의 문제가 아니다(합계 −10.1%).

### B-2. 백매터 헤딩 레벨을 스킬 템플릿과 다르게 잡았다

`book-editing` 스킬의 출력 템플릿은 `## 에필로그` · `## 참고문헌`(H2)이다. **H1으로 올렸다.**

**사유:** `build_epub.sh`가 `--split-level=1`로 빌드한다. 백매터를 H2로 두면 에필로그·부록·참고문헌이 전부 **12장 파일 안으로 흡수되고** EPUB 목차에서 12장의 하위 항목으로 들어간다. 프런트매터(`## 판권`·`## 머리말`·`## 목차`)는 템플릿 그대로 H2로 두었다 — 이쪽은 책 제목 H1 아래 묶이는 게 의도된 동작이다.

결과: H1 섹션 16개(제목 1 + 본문 12 + 백매터 3). 스킬의 **배치와 섹션 이름은 그대로 따랐고 레벨만 빌드 정합성에 맞췄다.** 템플릿 자체를 손볼지는 하네스 소관이라 여기서는 건드리지 않았다.

### B-3. 참고문헌은 "인용한 것"만 실었다

`01_reference.md` §6의 71개 항목 중 **본문이 실제로 인용한 소스만** 재정렬해 실었다(66개 번호 · 논문은 8편 + 배경 1편).

빼놓은 것 중 큰 덩어리는 **본문에서 인용하지 않은 논문 9편**(2503.23278 · 2509.24272 · 2508.13220 · 2603.22489 · 2512.08290 · 2602.11327 · 2607.10123 · 2302.04761 · 2307.16789 · 2606.04990)이다. 리서치는 읽었지만 본문 주장의 근거로 쓰이지 않았고, 목록에 올리면 "이 책이 그 위에 섰다"는 인상을 주게 된다.

계획이 요구한 **"동료 심사 확인 3편 먼저 배치"는 지켰다.** 셋 중 ReAct(2210.03629, ICLR)만 본문 미인용이라, 목록에 두되 **"본문에서 직접 인용하지는 않았다"고 항목 안에 명시**했다.

레퍼런스가 경고한 인용 주의 3건도 그대로 반영했다.
- MCPTox(2508.14925): 게재판 제목을 정본으로 쓰고 **arXiv판 제목에 "Attack"이 붙어 있다는 차이를 항목에 명기.**
- 2603.22489(MDPI 저널판과 동일 연구 가능성, "두 편으로 세지 말 것") — 미인용이므로 목록에서 제외해 문제 자체가 소멸.
- Toolformer(2302.04761, "게재처 단정 금지") — 미인용이므로 제외.

### B-4. 부록은 색인이지 새 내용이 아니다

부록의 모든 항목에 근거 장 번호를 달았다. **새 보안 주장은 한 줄도 추가하지 않았다** — 팩트체크 게이트가 닫힌 뒤에 검증되지 않은 사실이 들어가는 것을 막기 위해서다. 검수 시 각 줄을 해당 장에서 역추적할 수 있다.

수치는 본문 표현을 그대로 옮겼다(19% · 72.8% · 3% 미만 · 2,048자 · 8종 중 3종 · CVSS 9.4 · `0.14.1` · 245개는 옮기지 않음).
