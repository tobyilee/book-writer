**"Claude Code 경험자 관점" 유지 (직접 실측).** 12개 장 전부에 대응 축이 있으나 밀도 편차가 크다 — 명시 언급은 1장 10회 / 3장 9회 / 2장 7회 / 5장 3회 / 12장 1회 / **4·6·7·8·9·10·11장 0회**. 다만 이는 **계획 규율 12(Claude Code 화이트리스트)의 직접적 결과**다. 규율이 "Claude Code 쪽을 새로 정의하지 말라"고 봉인했으므로, 뒤쪽 장들은 "익숙한"·"손에 익은"·"다른 도구"·"여기서 갈린다" 같은 우회 문형으로 축을 유지한다(전 장 실재 확인). 규율을 지킨 대가이므로 미달로 계상하지 않는다.

**아슬 — 10장이 대응 축이 가장 얇다.** "Claude Code" 0회, "대응" 0회이고 축은 「부품으로 붙는가」 절이 "다른 에이전트"로 일반화해 담당한다. 계획이 이 장에 배정한 대응 포인트("Codex Security는 대응 제품 없음 — MCP로 노출되므로 조합 가능")는 그 절이 정확히 수행하되, **MCP 노출 범위가 읽기 전용 `info` 하나뿐**이라는 사실 확인 때문에 "그대로 쓸 수 있다"는 낙관적 결론은 내려가 있다. 사실이 계획을 이긴 정당한 조정으로 본다.
