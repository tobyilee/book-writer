## 계획 단계 시드 (Phase 3, 라운드 1 리뷰 반영)

### FR-1. 🕒 GPT-5.4 / GPT-5.4-mini 은퇴는 **미래 시제**로 쓴다

- **레퍼런스 §3-1·§7-4 #1의 "이 책이 나오는 시점엔 이미 지난 날짜다"는 무효다.** 레퍼런스 작성자가 집필 시점을 뒤로 가정한 오류이며, 계획 라운드 1(2026-08-02)에서 **오류로 확정·정정**했다. 오늘 기준 은퇴일(2026-08-31)은 **29일 뒤 미래**다.
- **채택 문안 (8장·12장 공통):**

  > `gpt-5.4`·`gpt-5.4-mini`는 **2026-08-31 은퇴 예정**이다(ChatGPT 로그인 사용자 한정 — API 키 인증은 영향 없음). 대체는 각각 Terra·Luna. **2026-08-02 문서 기준으로는 아직 은퇴 전이다.** 이 책을 읽는 시점에는 이미 지난 날짜일 가능성이 높으므로, 은퇴 여부가 아니라 **대체 경로**를 기준으로 읽어라.

- **금지:** "은퇴했다", "이미 은퇴한", "지난 8월 은퇴로" 등 과거형 서술.
- **저술가 주의:** 레퍼런스를 직접 읽고 이 정정을 되돌리지 마라. 되돌린 초안은 fact-checker가 ❌로 판정한다.

### FR-2. 시점 병기 문안은 `(2026-08-02 문서 기준)` 하나로 고정

### FR-9. 리서치 파일의 "총 N개" 라벨을 그대로 옮기지 마라 — 세어라

파 1 최대 오류(1장 "changelog 항목 95개")의 원인이다. `research/web-1.md`의 라벨(95)과 **같은 파일의 전수 색인**(87행)과 **원문 캐시 실측**(81)이 삼중으로 어긋났다.

- **규칙:** 리서치 파일(`research/web-*.md`·`community*.md`)의 요약 라벨에 등장하는 개수·총량 수치는 **근거가 아니라 단서**다. 본문에 정확 수치를 쓰려면 `research/codex-docs-raw/`에서 **직접 세라.**

### FR-10. 표 캡션이 "원문 표"라고 말하면 셀은 원문 문자열이어야 한다

### FR-11. 날짜는 "주간"과 "일자"를 구분해서 옮겨라

- 주간 섹션에만 있는 항목을 일자로 특정하지 마라. "7월 20~24일 주간에"처럼 주간으로 적는다.

### FR-12. Claude Code 부재 주장(`~가 없다`)은 §4-4로도 못 만든다

3장의 `(사실 확인 필요)` 마커(Steering/Queuing 2모드)가 여기 걸렸다.

- **§4-4는 "Claude Code에만 있는 것" 목록**이다. 어떤 항목이 §4-4에 **없다는 사실**은 "Claude Code에 그것이 없다"의 근거가 **되지 않는다.** 마찬가지로 §4-3(Codex에만 있는 것)에 없다는 사실도 근거가 아니다. **목록의 부재는 사실의 부재가 아니다.**
- 화이트리스트 3절 어디에도 없는 대비를 쓰고 싶으면, **주장을 Codex 쪽 진술로 돌려라.** 안전 문형:
  > "Codex는 X를 A·B·C로 갈라 노출한다. **~해오던 손이라면 여기서 갈린다.**"
  Claude Code 쪽을 정의하지 말고 독자의 기존 감각에만 말을 건다. 수사적 효과는 그대로 남고 사실 주장은 사라진다.
- ⚠️ **`01_reference.md`에 그 문장이 있다는 것은 통과 사유가 아니다.** 레퍼런스 §3-6·§4-5에는 화이트리스트 밖 Claude Code 주장이 실려 있다. FR-3이 레퍼런스보다 우선한다.

3. **은퇴 문안 중복 확인.** 8장·12장에 문자 단위로 동일한 문안이 있다. 에필로그가 이를 세 번째로 옮긴다면 **또다시 문자 단위로 같아야** 한다(FR-1).
4. **서문·에필로그의 요약 수치.** "12장", "148개 URL / 고유 문서 약 140개", "설정 키 270개가 넘고" 같은 집계가 부속에서 재등장하면 **FR-16을 다시 적용**하라 — 이 책의 ❌ 6건 중 5건이 집계에서 났다.
5. **뒷부속에 새 사실을 도입하지 마라.** 부속은 본문에서 확인된 것만 회수한다. 새 주장이 나오면 그것은 검증되지 않은 주장이다.
