## 1장. 두 개의 피드백 루프 — 우리는 왜 한쪽만 설계했나

### 라운드 1 (writer-1 요청)

- **오프닝 기법:** 계획 배정 = 인용·일화(HN Quarrelsome). 초안 = HN "AI is making me dumb" + Quarrelsome 인용으로 진입. ✅ 배정 준수, 메타 선언 없음, 인접 2장(실패 장면)과 겹침 없음.
- **분량:** 약 10,250자 (프레이밍 장, 계획 11,000 범위 내). 6개 ## 섹션, 나열식 문단 없음.
- **신선도 규율:** 우수. Octoverse 2025(발표·스냅샷 시점 명기)·InfoQ 2025-06·배민 이재홍 2026-04 모두 시점 못 박음. `(사실 확인 필요)` 잔여 없음. 추측 API 없음.
- **클로징:** ✅ "다음 장에서는~" 공식 아님. 변주된 이음말 + 2장 오프닝 이미지(새벽 2시 스택 트레이스) 시딩 — 좋은 콜백-포워드.
- **mermaid 그림 1:** 규약 준수(그림 N 캡션, 챕터 내 1부터).

**주요 편차 (총 5건 — Critical 0 / Should 2 / Nice 3):**
- Should S1: 64줄 수사적 질문 3연속(정말 그럴까? / 잘 돌아가고 있을까? / 녹슬고 있을까?) → 첫 물음을 평서로 눌러 물음표 축소 제안.
- Should S2: "…밤을 떠올려 보자" 도입 장치 2회 반복(45줄·106줄) → 하나 변주 제안.
- Nice N1: 86줄 한 문단 bold 2개 → 두 번째(한참 뒤로 미뤄져서) 해제 제안.
- Nice N2: 43줄 문장 통째 bold → 개념어(복리)만 남기기 제안.
- Nice N3: 74줄 "94% … 집계도 있다" — 시점·출처 명기돼 style OK. fact-checker 대조 대상으로만 이월(수정 불요).

**writer 특정 질문 답변:** tic 과포화 없음(청유형 ~11회/10,250자 자연 범위, 단 S2 반복만 변주) · 공감 표현 "찜찜함" 2회=밴드 내 ✅ · 수사적 질문 대체로 전환 지점, S1만 3연속 · 클로징 변주 ✅.

**해소 여부:** 회신 발신 완료, writer-1 반영 대기.

## 4장. 하네스의 마지막 게이트는 사람이다

### 라운드 1 (writer-2 요청)

- **오프닝 기법:** 계획 배정 = 충격적 수치(Osmani 70%/30%). 초안 = "AI는 당신 일의 70%를 해낸다. … 진짜 문제는 나머지 30%에 있다." ✅ 배정 준수, 메타 선언 없음, 인접 3장(정의 뒤집기)·5장(상황 가정)과 상이.
- **분량:** 약 12,200자. 5개 ## + 3개 ### 소절(답 하나/둘/셋). 나열식 문단 없음.
- **커뮤니티 인용 정직성:** 우수. largbae(컴파일러)·devolving-dev(계산기)·pton_xd(단언)·georgemcbay(사회 확장) 모두 희화화 없이 인용하고 "이 논거들엔 힘이 있다"고 명시 존중. 계획 요구(반대 진영 존중) 정확히 이행.
- **신선도 규율:** 우수. Osmani 2025-03·Anthropic·Koli 2023·AI&Society 2025·Nature Comp Sci 2025 전부 시점·출처 명기. 79줄에 재현 부족·논평 성격 유보 병기. `(사실 확인 필요)` 없음. 추측 API 없음.
- **메타 문장/강압:** "이 장에서는~" 금지 준수 ✅. 강압("반드시 ~해야") = 21줄 1회뿐이며 원칙 설명용(expository)이라 무해.
- **tic:** 수사적 질문·연결어 잘 분산됨. 3연속 없음. 공감어는 적게 썼는데 논증 장이라 적절(의도적 비움 허용).
- **mermaid 그림 1:** 규약 준수.

**주요 편차 (총 4건 — Critical 0 / Should 3 / Nice 1):**
- Should S1: full-sentence bold 6~7건(31·65·81·95·129·143·157줄) → 핵심 2~3개만 남기고 핵심어 bold로 축소(밀도 상한 자체는 이내지만 문장 통째 강조 남발이 효과 희석).
- Should S2 (코디네이션): Anthropic pass/fail 인용이 1장("루프는 알아서 닫힌다")과 4장("루프는 스스로 닫힌다")에서 번역 불일치 → 한 표현으로 통일. editor 통합 단계 대상이나 조기 정렬 권고. **통권 점검 추적.**
- Should S3 (코디네이션): "금요일 마감+티켓 N개" 장면이 1장(106줄)·4장(63줄) 중복 → 하나 변주 권고. **통권 점검 추적.**
- Nice N1: 21줄 "반드시 … 분리되어야 한다" — 원칙 설명이라 무해하나 "반드시" 빼도 무방(선택).

**writer 특정 질문 답변:** tic 밴드 준수(분산 우수) · 강압 없음(21줄 1회 expository) · 메타 금지 준수 · 커뮤니티 인용 정직성 모범.

**해소 여부:** 회신 발신 완료, writer-2 반영 대기. S2·S3는 통권 점검으로 이월.

## 7장. 익숙한 스택을 떠날 때 — 잃어버린 checker를 다시 세우기

### 라운드 1 (writer-3 요청)

- **오프닝 기법:** 계획 배정 = 상황 가정(자바 10년차 월요일 FastAPI). 초안 준수 ✅. 직후 프론트 독자용 re-read 블록(7줄)으로 병렬 진입 — 계획 C1 대칭 서비스 이행. 5장도 상황 가정이나 비인접(6장 사이), 2/9=22% 규정 준수. 인접 6·8장과 기법 상이.
- **분량:** 약 13,300자(계획 17,000 대비 −22%). **스타일상 얇은 절 없음** — 프론트 병렬 섹션이 백엔드보다 가벼우나 이는 계획 설계(주 사례 vs 병렬 미니). 17k 도달은 콘텐츠 판단(프론트 병렬·METR 균형추에 예시 1개씩 추가 가능)이지 스타일 결함 아님.
- **콜백:** 1·2·3·4·5·6장 전부 재교육 없이 콜백으로 연결. 적용 장의 모범. 콜백 어구도 대부분 변주됨("떠올려보자" 2회는 콜백 관용구라 허용).
- **신선도 규율:** 우수. Octoverse 2025·GitHub 2025(94%)·FastAPI 공식 인용 전부 시점 명기. 85줄 Pydantic 예시에 "버전 따라 달라질 수 있으니 공식 문서 확인" 휘발성 경고 — voice §6 모범. 추측 API 없음(Pydantic 코드 정확).
- **"이 장의 핵심" 박스(141줄):** 헤딩 정확(### 이 장의 핵심)·5불릿·새 정보 없음 — 형식 완벽. 단 현재 이 박스를 쓴 장이 7장뿐(1·4장 미사용) → 책 전체 채택 여부 정렬 필요(통권 점검 추적). 박스 자체는 규약 준수, 지금 수정 불요.
- **mermaid 그림 1:** 규약 준수. bold는 핵심어·절차 라벨 위주로 잘 통제됨(4장보다 우수).

**주요 편차 (총 3건 — Critical 0 / Should 2 / Nice 1):**
- Should S1: "개운하지 않다" 계열이 첫 섹션에 3회 밀집(5줄·9줄 헤딩·19줄) → 19줄 하나만 다른 표현으로 변주(모티프는 유지).
- Should S2 (코디네이션): "이 장의 핵심" 박스 책 전체 채택 여부 결정 필요 — 7장 단독 사용 상태. **통권 점검 추적.** 박스 자체 무결.
- Nice N1: 107줄 "이 이야기를 조금 뒤에서 이어가보자" 장내 전방 참조가 다소 모호 → 무엇을(다이얼) 이어갈지 살짝 구체화 가능(선택).

**writer 특정 질문 답변:** 얇은 절 없음(프론트 병렬은 의도적 경량) · tic 과포화 없음(공감어 7회/13,300자 자연 범위, 단 "개운찮" 첫 섹션 밀집만 S1) · 수사적 질문·청유형 분산 양호.

**해소 여부:** 회신 발신 완료, writer-3 반영 대기. S2는 통권 점검으로 이월.

## 5장. 흐름 안에서 배우기 — 상호작용 기본값을 하네스에 새기기

### 라운드 1 (writer-2 요청)

- **오프닝 기법:** 계획 배정 = 상황 가정(CLAUDE.md 규칙 한 줄). 초안 준수 ✅. 메타 선언 없음. 인접 4장(수치)·6장(수사적 질문)과 상이.
- **분량:** 약 13,200자. 6개 ## 섹션. 코드/설정 블록 다수(CLAUDE.md·settings.json 훅·커스텀 커맨드·TDD Red·Cursor Rules).
- **코드 접합부 톤:** 대체로 유지 우수 — 코드 뒤 설명이 "손이 기억 못 해도 명령이 기억한다"류 온기·권장형으로 잘 이어짐. 단 코드 앞 도입구 tic(S2).
- **신선도 규율:** 88줄 훅 휘발성 경고("2026 기준·공식 문서 확인·빠르게 바뀜") 모범. 생성효과 1978·testing effect 2006·Octoverse 2025 시점 명기. 단 94% 수치 시점 앵커 누락(S3). 추측 API 없음(훅 예시 illustration 명시).
- **셀프 레퍼런스 담백성:** 우수. 160줄 "이 하네스는 4장이 경고한 함정에 그대로 노출된다"는 자기비판적 프레이밍이 자화자찬을 차단. 174줄 메타 문장은 허용 범위.
- **tic:** 수사적 질문·청유형 분산 양호, 3연속 없음. 공감어 적음(how-to 장이라 적절).
- **mermaid 그림 1:** 규약 준수.

**주요 편차 (총 6건 — Critical 0 / Should 4 / Nice 2):**
- Should S1: full-sentence bold 다수(37·116·118·139·160·174줄 등) — **writer-2 4장과 동일 패턴 재발**. 구조 라벨(기본값·도구 헤더)은 유지, 문장 통째 강조만 핵심어로 축소.
- Should S2: 코드 도입구 tic — "대략 이런 모양이다"(67)·"대략 이런 식이다"(141)·"이렇게 적을 수 있다"(53) 유사 반복 → 변주.
- Should S3: 94% 수치가 137줄에서 "한 조사에서"로만 제시, 1장("2025 스냅샷")·7장("GitHub 2025")의 시점 앵커 누락 → 앵커 추가 + 1장 콜백화 권고. **코디네이션:** Octoverse 2025 1위 + 94% 페어링이 1·5·7장 3회 반복 → 통권 추적, 후속 장은 재인용 대신 콜백.
- Should S4 (코디네이션): 5장 클로징(182줄)이 6장 배정 오프너(수사적 질문 "AI 없이 버그 쫓아간 게 언제")를 선반향 → 6장 실제 오프닝과 동일 질문 반복 회피(writer-2가 양장 소유하니 자체 조율 용이).
- Nice N1: 133줄 프론트 섹션 헤딩 "프론트엔드 개발자를 위한 (React·Next.js·TS)"이 잘림 → 명사 보완(예: "…를 위한 흐름 안 기본값").
- Nice N2: "짚고 넘어가자" 2회(106·135) → 하나 변주(선택).

**writer 특정 질문 답변:** 코드 접합부 톤 유지 우수(S2만) · tic 과포화 없음 · 훅 휘발성 경고 모범(단 94% 앵커 S3) · 셀프 레퍼런스 담백·자기비판적, 자화자찬 없음.

**해소 여부:** 회신 발신 완료, writer-2 반영 대기. S3(페어링 반복)·S4는 통권 점검 이월.

## 8장. 주니어를 위한 다른 지도 — 사다리가 흔들릴 때

### 라운드 1 (writer-3 요청, 7장과 배치)

- **오프닝 기법:** 계획 배정 = 인용·일화(evan-moon). 초안 = "10년을 일해도 1년짜리 경험을…" 인용 진입 ✅. 메타 선언 없음. 인접 7장(상황 가정)·9장(콜백)과 상이.
- **분량:** 약 15,000자(계획 부합). 5개 ## + 2개 ### 소절 + 핵심 박스. 주니어 standalone 독해 설계(9줄 명시, 개념 in-place 재설명) 이행.
- **expertise reversal 보호 단서:** §2(29~35줄) 전면 배치 — "생성 효과는 사전지식 필요"+"초보엔 넉넉한 안내" 강조. **계획 최우선 요구를 정확히 이행.** 우수.
- **신선도/사실:** 인과 회피·시점 hedge 모범(15·17·19줄). `(사실 확인 필요)` 마커 = 19줄 Voss −28%/6.1%에 **올바르게** 배치(원 출처 대조 지시 포함). 정상 이월. 86줄 BLS 두 자릿수도 fact-checker 대상.
- **tic:** 수사적 질문 8개 = **과포화 아님**(15,000자에 전환점마다 분산, 3연속 없음). 공감어 적정.
- **클로징:** ✅ 시니어 소절 뒤 9장(인지 작업 소유권) 시딩. 핵심 박스 규약 준수.

**주요 편차 (총 4건 — Critical 0 / Should 2 / Nice 2 + 팩트 이월):**
- Should S1 (코디네이션): 개인 개발자 인용을 "한 개발자"로 익명 처리(evan-moon·teo 등) — 1장(Quarrelsome)·4장(largbae 등)은 핸들 명기. 귀속 관례 책 전체 통일 필요. **통권 추적.**
- Should S2 (코디네이션): "이 장의 핵심" 박스 — writer-3(7·8장) 사용, writer-1/2(1·4·5장) 미사용 → 저술가별 편차. 책 결정 필요. **통권 추적.**
- Nice N1: 70줄 한 문단에 3개 논지(AI 답답 간극+답변기/튜터+의도 증폭) → 분할 고려.
- Nice N2: "그려보자" 2회(54 헤딩·56 본문) — 매우 경미.
- 팩트 이월: 19줄·86줄 fact-checker 필수 확인(정상 프로세스, style 결함 아님).

### 7→8→9 흐름·용어 일관성 점검(writer-3 요청)
7장 클로징("안전망 없는 이들")→8장(주니어) 브리지 ✅. 8장 클로징→9장(인지 작업 소유권) 시딩 ✅. 용어(위임 다이얼·생산/학습 모드·흐름 안/밖·checker·생성 효과) 3장 일관 ✅.

**해소 여부:** 회신 발신 완료(9장과 통합), writer-3 반영 대기.

## 9장. 인지 작업의 소유권 — 좋은 하네스가 길러내는 엔지니어

### 2. 클로징 획일성 — Should 1건

- "다음 장에서 ~ 보자" 공식이 2장(326줄)·3장(455줄)·7장(1078줄) 3곳. 7장은 "다음 장에서 만날 사람들"로 구문이 달라 무해. **2장·3장이 연속 챕터인데 "다음 장에서 [목적어] [청유]" 구문이 거의 동일** → 독자가 두 장 연속 같은 이음말을 만남.

### 3. Decision 1 — "### 이 장의 핵심" 박스 → **(a) 두 박스 제거 권고**
